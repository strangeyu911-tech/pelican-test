# 《鹈鹕测试》制作计划 v1.0

> 一支约 2:17 的代码动画短片。鹈鹕骑自行车，沿一条贯穿全片的路，穿过 20 个艺术史版块。
> 本文档 = 预研结论 + 架构设计 + 风险判断 + 需要拍板的决策点。

## 一、预研结论（已实测，不是估算）

### 1.1 本机环境：全部达标

| 项 | 要求 | 实测 | 结论 |
|---|---|---|---|
| Node | 20+ | v22.22.2 | ✅ |
| ffmpeg | 需要 | 9.0-full_build | ✅ |
| Chrome | 需要 | 156.0.8078.48 | ✅ |
| Git / gh | — | 2.55.0 / 2.96.0 | ✅ |
| GPU | — | **Intel UHD Graphics 630（集显）** | ⚠️ 唯一短板 |

WebGL 后端：`ANGLE (Intel UHD Graphics 630, Direct3D11)`。没有独显，所以下面所有性能数字都是集显成绩——换独显只会更快。

### 1.2 性能实测：结论只有一个——必须烘焙

用真实的水墨山水场景（~200 笔 p5.brush）测出：

| 方案 | draw | 导出 PNG | 单帧合计 | 全片 30fps（单线程） |
|---|---|---|---|---|
| **A. 每帧从零重画** | 140 ms | 178 ms | **318 ms** | **21.8 分钟** |
| **B. 静态层烘焙 + 每帧 blit** | 1.1 ms | 32 ms | **33 ms** | **2.3 分钟** |

**差 9.6 倍。** 这不是优化建议，是架构硬约束：

- `p5.brush` 的笔触是立即合成的，**没有增量重绘**。每帧重画 = 每帧付全额成本。
- 烘焙后每帧只剩一次纹理 blit（1.1 ms），几乎免费。
- 烘焙本身约 143 ms/场景，但**每个场景只付一次**，且可以进一步预烘焙成磁盘 PNG 跨进程复用。

结论：**"静态层烘焙 + 动态层逐帧"是唯一可行路径。** 60fps 也只要 4.6 分钟，性能完全不是瓶颈。

### 1.3 两个踩过的坑（已解决，写进工具链）

- **坑 1：CDP 截图全黑。** p5 2.x 会把 canvas 塞进它自己创建的 `<main>`，若页面上有占位 div，canvas 会被挤到视口外（实测 y=1080）。CSS 必须 `main{position:fixed;inset:0}`。
- **坑 2：`page.screenshot()` 慢且不稳。** 改用页面内 `canvas.toBlob()` → ArrayBuffer → Node 写盘，**21~32 ms/帧，比 CDP 截图快 1.7~2.6 倍**，且不受合成时机影响。

## 二、架构

### 2.1 坐标系统

```
舞台   1000 × 1000 单位   （所有场景在此作画，也是"画框"的四边）
换算   1 单位 = 1.08 px   （1000 单位铺满 1080 高度）
视口   1920 × 1080 px  =  1777.8 × 1000 单位
两侧   各 420 px "溢出区"  （画延伸内容，保证满屏无黑边）
```

也就是说：**1000×1000 是必须完整可见的核心构图区，两侧 420px 是 over-scan 安全区**。画框正好落在核心区的四边，16:9 视口能看到画框 + 两侧一点"画框外的世界"。这既满足"1000×1000 内作画"，又保证满屏。

### 2.2 目录

```
src/kit/        共用绘图工具包
                  frame.js     坐标/镜头/缓动/随机（可播种）
                  ink.js       水墨渲染器（版块 3/4/5/6/9 共用，参数化笔法）
                  paper.js     纸/岩/绢/拓片等底材生成器
                  text.js      文字（含标题卡、竖排、外文）
                  layer.js     图层与烘焙管理
src/beat/       节拍与时间轴（唯一真相源，导出 timeline.json）
src/rig/        鹈鹕 + 自行车骨骼木偶
                  rig.js       骨架解算：pose(t) -> 关键点
                  pelican.js   造型绘制（按风格参数化）
                  bike.js      车体绘制
src/scenes/     每版块一个文件，纯函数 renderAt(t) 或 draw(t, u, meta)
src/main.js     调度、转场、镜头
tools/          render.mjs（逐帧）/ sheet.mjs（接触表）/ shot.mjs（单帧）/ encode.mjs
briefs/         每版块美术简报 + STYLE.md 共用规格
audio/          合成配乐（实时版 + 离线版）
public/         预览页 + vendor
docs/           本计划、接触表、验收记录
```

### 2.3 纯函数与烘焙的分工

每个场景必须暴露：

```js
V.scenes.song = {
  t0, t1,                      // 由 timeline 注入
  duration: 6,                 // 版块时长
  bake: (stage) => {...},      // 【只在首帧调用一次】静态层：山、天空、纸纹、画框
  draw: (t, u, ctx) => {...},  // 【每帧】动态层：骑手、路面滚动、粒子、梗的演出
  layers: 3,                   // 视差层数：远/中/近
}
```

主循环：

1. 首帧：`bake()` 把静态层按视差层数烘成 N 张 `p5.Graphics`
2. 每帧：按镜头参数平移 N 层（每层 1 次 blit）+ 画动态层
3. 转场：两个场景同时 live（各自烘焙一次缓存），合成时用遮罩

**视差是"烘焙"和"路面滚动"的调和方案**：不是把整幅画烤死，而是烤成 3~4 层，每层独立平移。镜头推近 = 各层按不同比例缩放。这既省算力，又让画面"活"。

### 2.4 转场（我们的差异化设计）

不用百叶窗、不用年份计数器。用**"穿过画框"**：

```
t ∈ [B-0.30, B+0.30]        B = 版块边界
  0.00 → 0.35   画框 A 的四边向外扩张，画面从中向外"溢出"
  0.15 → 0.85   B 的场景透过扩张的洞口显现
  0.60 → 1.00   画框 B 的四边从视口外收拢到位
  全程          镜头 scale 1.00 → 1.06 → 1.00（轻微推近）
```

路面的处理是关键：**每个版块里路的位置完全相同**（y 固定、坡度固定），所以穿过去时路是接的。画框材质随时代变化（岩壁裂口 / 莎草纸卷边 / 拓片纸边 / 绢本包边 / 金花边框 / 皮影戏幕布口 / 屏幕边框…）。

特殊转场 14→15（诺斯费拉图 → 示波器）：影子轮廓在强拍上"通电"，沿轮廓注入绿色辉光线条，同时画框从"墙上的方洞"变成"示波器的圆形荧光屏边框"。

## 三、时间轴（精确到帧）

120 BPM，1 拍 0.5s，1 小节 2s。

| 段落 | 小节 | 时间 | 时长 |
|---|---|---|---|
| Intro | 0 – 3 | 0 – 6 s | 6.0 s |
| 版块 1–20 | 3 – 63 | 6 – 126 s | 每格 3 小节 = 6.0 s |
| Outro | 63 – 69 | 126 – 138 s | 12.0 s |
| **总计** | 69 小节 | | **138 s = 2:18** |

版块 i（i = 1..20）：`t0 = 6 + 6(i-1)`，`t1 = t0 + 6`

内部三小节：

| 小节 | 局部时间 | 内容 |
|---|---|---|
| 第 1 | u ∈ [0, 2) | 进场：骑手从画框外进入，路面开始滚，标题卡淡入 |
| 第 2 | u ∈ [2, 4) | 梗 / 高光（可放慢定格） |
| 第 3 | u ∈ [4, 6) | 骑向下一道画框，标题卡淡出 |

过画框的强拍：`t = 6, 12, 18, … 126` —— **全部落在小节线上（强拍）**。
脚踏一圈 = 两拍 = 1.000 s，全片统一。

## 五、音乐方案（我的强建议）

原始需求是"每个版块换成那个时代或地域的乐器"，20 段配乐。**如果按字面做，这是整个项目最大的翻车点**——程序合成硬凑"古琴""西塔琴""甘美兰"，大概率变成"电子琴假装民族乐器"，比不做音乐还糟。

我的方案：**主题 + 音色** 两层解耦。

1. **主题层（统一）**：主旋律写成一份音符数据 `motif.json`（音高 + 时值 + 重音），全片 20 个版块共用同一份动机，只做变奏。
2. **音色层（差异化）**：不追求"像真乐器"，而是用**物理建模三要素**（激励 → 共振体 → 包络）做出**该乐器的行为特征**：
   - 编钟：低频强、衰减极长、非谐分音
   - 古琴：窄带共振 + 大量微分音滑音 + 长余韵
   - 西塔琴：持续嗡鸣（drone）+ 弯音
   - 甘美兰：金属快速衰减 + 成对失谐（ombak）
   - 三味线：短促拨弦 + 明显噪声瞬态
   
   这些特征用 Web Audio 的 FM + 加法 + 滤波器 + 包络完全做得出，而且**行为对了就"像"，音色不准反而有风格化美感**。
3. **地域感靠调式，不靠音色**：五声音阶（中国）、slendro/pelog（爪哇）、raga（印度）、maqam（莫卧儿）。调式一换，地域感立刻成立，比硬调音色有效得多。

蒸汽波那格的数学我核对过，**你写的参数全对**：

- 151.2 BPM × 0.7937 = 120.0 BPM ✓
- 0.7937 = 2^(-4/12) → 降 4 个半音 ✓，所以素材调性必须高 4 个半音 ✓
- 补一条实现细节：`playbackRate` 已同时改变速度和音高，**不能再叠加 detune 补偿**；0.5Hz 的"磁带摇晃"要用独立的 `detune` LFO 叠加在 `playbackRate` 之上（两者是乘性/加性独立参数，可以共存），偏移量控制在 ±8~12 cent，再多就听出是故障了。
- 跳针效果：`AudioBufferSourceNode` 不能中途 seek，需要在第 2 小节预先起一个短 `AudioBufferSourceNode`（半拍 = 0.25s 素材），循环 3~4 次再切回主源。

## 七、需要你拍板的 5 个决策

### D1 ★ Intro 时长与"强拍"的矛盾（必须解决）

你写的 **Intro 2.5 小节 = 5 秒**，与 **"每次过画框都落在强拍上"** 数学上冲突：

- 版块边界 = 5, 11, 17, 23 … 秒
- 小节线 = 0, 2, 4, 6, 8, 10, 12 … 秒
- **5 秒、11 秒都落在小节的第 3 拍（次强拍），不是强拍（第 1 拍）**

三个解法：

| 方案 | 总长 | 效果 |
|---|---|---|
| **A（推荐）** Intro 改 3 小节 = 6 s | 138 s = 2:18 | 全部边界落在强拍，数学最干净，多出 1 秒给"第二条字幕 + 鹈鹕骑入"呼吸 |
| B | Intro 保持 2.5 小节 | 137 s = 2:17 | 音乐网格整体相位偏移 −1 s，让 5 秒变成小节线；代价是 Intro 弦乐从"残句"进 |
| C | Intro 2 小节 = 4 s | 136 s = 2:16 | 边界也在强拍，但两条字幕 + 出处只有 4 秒，太赶 |

**我推荐 A。** 多 1 秒换全片节奏的数学干净，值。

### D2 ★ 1000×1000 与 16:9 的关系

正方形舞台放进 16:9，两侧各空 420px。两个选择：

- **A（推荐）** 1000×1000 = 核心构图区 + 画框四边；两侧 420px 为 over-scan 溢出区，画延伸内容保证满屏。视口永远满幅。
- B 画框严格正方形居中，两侧露出"墙面/裱边"（美术馆感，但每格都有 420px 的空白带，连续 20 格会很空）

**我推荐 A**，并且让"画框"成为转场的物理主角——因为路是连续的长卷，两侧必须是路和景的延续，不能是墙。

### D3 帧率

数据说话：30fps → 2.3 分钟渲染；60fps → 4.6 分钟。**两个都完全可承受，性能不构成决策依据。**

我的建议：**30fps**。理由：这是风格化动画，30fps 足够；复古格（10/16/17）本来就要量化到 8–12Hz；60fps 只让文件体积翻倍。但仍按你的要求，**阶段 1 出一段镜头平移对比片**（30 vs 60 并排），你看过再定。

### D4 版块时长是否允许弹性

现在每格严格 6.0 秒。但有个格明显不够：

- **20 代码美学**：6 秒要"逐行写出 SVG 代码 + 鹈鹕被一笔笔画出来"，观众还要读得清代码。6 秒 = 180 帧，按每秒 5 行只有 30 行，很紧。
- **5 宋代山水**："鹈鹕小到几乎看不见，镜头推近才找到"——推镜需要时间。

建议：**20 格给 4 小节（8 秒），5 格给 4 小节（8 秒）**，从 11 浮世绘、16 8-bit 各挪 1 小节（这两格的梗 6 秒内讲得完）。总时长仍是 138 秒。

要不要这么做，你定。**默认我按"全部 6 秒"执行**，除非你说改。

## 八、阶段划分与验收标准

每个阶段结束**停下给你看 demo**，你点头再进下一阶段。

### 阶段 1 — 骨架（无声音）

- kit / beat / rig / main 完成
- Intro 字幕（真实字体、真实排版）
- 路面长卷（可持续滚动，接缝无缝）
- 会踩踏板的鹈鹕（造型可辨认，动作连续）
- 20 个标名占位色块（每块显示编号 + 中文名 + 年代）
- Outro 7×3 展墙拉远
- 跑通逐帧导出 + 接触表
- **交付**：`preview.html`（可拖动进度、显示当前版块名）+ 一段 MP4 粗剪 + 接触表 PNG

**验收**：全片节奏对不对、鹈鹕认不认得出来、路接不接得上、转场位置准不准。

### 阶段 2 — 标尺 3 格

- 撒哈拉岩画 / 宋代山水 / 竖屏短视频，做到"能看"
- **交付**：3 段 MP4 + 接触表 + 每格 3 张关键帧大图

**验收**：这三格是否达到"美术馆级仿古"的标准。这一关决定后面 17 格的水平线。

### 阶段 3 — 其余 17 格（5 批）

- 先写 17 份美术简报（含色票、构图、笔法、节拍表）
- 每批出接触表 → 你验收 → 下一批
- **交付**：每批 MP4 片段 + 接触表

### 阶段 4 — 音乐

- 实时版（Web Audio）+ 离线版（OfflineAudioContext → WAV）
- 两版逐版块对拍，误差 < 1 帧
- **交付**：带声音的完整片 + 音频分轨

### 阶段 5 — 打磨与成片

- 转场微调、节奏微调、色彩统一
- 最终 MP4（1080p）+ 封面

## 九、我现在的判断

**技术上没有拦路虎。** 管线跑通，性能 2.3 分钟出全片，合规干净。

**真正的考验是审美和耐心。** 20 个版块每一个都要"像那个时代的真迹"，这没法靠聪明绕过——只能一格一格地：找真实参考 → 拆笔法 → 分层画 → 出图 → 自己看 → 改 → 再看。

我最担心的三格：**宋代山水**（水墨的墨色层次最难）、**莫卧儿细密画**（金色花边和透视）、**代码美学**（既要真代码感又要好看）。
